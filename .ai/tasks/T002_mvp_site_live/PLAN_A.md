# Plan A (Claude Code) — T002 MVP site and live schedule

Author: Claude Code

## Objective
A static MVP site generated by the pipeline itself from `listings.json`, a light gate that checks it, and a workflow that deploys it to GitHub Pages after a passing run, all with the repository's built-in token so Po can see real, trust-ranked repos at a URL without creating any account or secret.

## Assumptions
- `listings.json` schema is `pipeline.export.Listings` (rows are `PublishedListing` with `coverage`); the generator reads it only, never the state store.
- Labels remain provisional or pending and `tested` is `untested`; the site shows them as such, with a short note linking to "how we grade".
- `GITHUB_TOKEN` can call GraphQL (yes, with the repository's permissions) and `gh release upload/download` on the same repository (yes, with `contents: write`). Verified in a test the workflow runs on its first dispatch, documented as an owner step.
- Pages deployment uses the Actions artefact route, so no `gh-pages` branch.

## Proposed architecture
`pipeline/site/` = `templates/` (Jinja2: `base.html`, `index.html`, `topic.html`, `repo.html`, `how_we_grade.html`), `build.py` (load `Listings`, derive topic groups and the top ten by score, render pages, write `status.json` with `generated_at`, `run_id`, data age, gate results), `links.py` (internal link check and page size bound), `static/site.css` (inline or copied). CLI subcommand `pipeline site build [--listings PATH] [--out PATH]`. Gate 5 light = `links.check(dist)` wired into the gate list so `pipeline run` fails the run if the site does not build. Workflow: after `pipeline release push`, `pipeline site build`, `actions/upload-pages-artifact`, then a `deploy` job with `actions/deploy-pages` and `environment: github-pages`. Markdown to HTML for `how_we_grade` via `markdown-it-py` (new runtime dependency with Jinja2).

## Numbered tasks
1. **Site generator and templates** — `pipeline/site/build.py`, templates, CSS; `pipeline site build` in `cli.py`. Depends: none. Tests: build from the 50-row dry-run fixture (recorded JSON fixture, sanitised) produces index, topic pages, 50 repo pages, how_we_grade, status.json; HTML escapes descriptions; every listing field named in the request appears on the repo page. Risk: medium.
2. **Light gate 5** — `pipeline/site/links.py`: every `href` to an internal path resolves to a file in `dist`, no page over 200 KB, index has at least one topic; registered as gate 5 in `gates.py` and run inside `pipeline run` after export (dry run builds to `site/dist.dry/`). Depends: 1. Tests: broken link and oversize page fail; clean build passes. Risk: low.
3. **Workflow and Pages deploy** — extend `refresh.yml`: build the site after a passing run, upload the Pages artefact, `deploy` job with `pages: write`, `id-token: write`; replace `GH_TOKEN: ${{ secrets.GH_TOKEN }}` with `${{ github.token }}` and document the token's limits in the runbook (GraphQL rate limit shared per repository, release asset only on the same repo); `tests/test_workflow.py` extended for the new steps and permissions; `README.md` "Live site" section with the Pages URL pattern and the owner go-live steps. Depends: 2. Tests: YAML parse, steps and permissions present, no `secrets.` reference left. Risk: medium.
4. **Local acceptance run** — `pipeline run --dry-run --limit 20` then `pipeline site build` against `listings.dry.json`; open `site/dist/index.html` locally; record page counts and sizes in the handover. Depends: 3. Risk: low.

## Implementation order
1, 2, 3, 4.

## Test strategy
pytest with a recorded 50-row listings fixture; `--cov-fail-under=80` kept; ruff clean; the local acceptance run is the proof; the live deploy is an owner step at close-out with the runbook describing what to expect.

## Risks
`GITHUB_TOKEN` GraphQL limit is per repository (1,000 points an hour on some plans): a full run uses 12 to 60 points, fine. Pages must be enabled with source "GitHub Actions" once by the owner. Markdown rendering of `docs/scoring.md` may need a header strip.

## Alternatives considered
Astro now (rejected for the MVP: Node toolchain, request 6); `gh-pages` branch deploy (rejected: artefact route is simpler and needs no branch).

## Rollback
Revert the request branch; the pipeline runs unchanged without the site steps.

## Open questions for the user
None blocking. Site name and tagline default to "AI_Hub" and "trusted starting points for coding agents".
